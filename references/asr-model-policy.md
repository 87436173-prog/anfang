# 全量主转写模型规范（Dolphin 主转写）

版本：`asr-dolphin-cn-dialect-2026-11-14-v1`
生效：2026-11-14 及之后开始处理的所有本地录音。2026-11-13 及以前已出图的接待不重转、不改分。

## 一、固定选型

| 环节 | 模型/引擎 | 说明 |
|---|---|---|
| 全量主转写 | **Dolphin-CN-Dialect `small.cn`**（DataoceanAI，ModelScope，`small.cn.pt`，约1.7 GB） | funasr 1.4.26 + PyTorch，CPU |
| 静音切分 | `speech_fsmn_vad_zh-cn-16k-common-pytorch` | 先 VAD 去静音，再逐段识别 |
| 高影响证据复核 | `ggml-large-v3-turbo-q5_0.bin`（本地）/ 云端 `large-v3-turbo` | 职责不变，只做定向窗口 |
| 争议二轮 / 分声道 | `whisper large-v3` 或 Turbo + 原始分声道 | 仅在 Dolphin 与复核冲突且需要判断"谁说的"时启用 |

whisper-small **退出主转写链路**，只保留三种用途：①历史任务复现；②Dolphin 与 Turbo 冲突时的第三意见；③需要依据说话人归属（B3 自报姓名与称谓、销售/客户对立陈述）而 Dolphin 单声道无法判定时的分声道补测。

调用脚本：`scripts/asr_dolphin.py`（技能自带副本），用法

```bash
# PYTHONPATH 指向 dolphin 虚拟环境根目录；线程数默认 6
python scripts/asr_dolphin.py <音频或wav> <输出.jsonl> --threads 6
```

输出每行 `{"t0": 厘秒, "t1": 厘秒, "text": "..."}`，与历史 whisper `transcript.json` 同 schema，`dump.py` 等既有工具可直接读取，无需改下游。

## 二、切换依据（2026-11-13 同文件双跑验证）

样本：18 条录音、825 分钟，Dolphin 与 whisper-small 对同一音频各跑一遍。

| 指标 | Dolphin small.cn | whisper-small |
|---|---|---|
| 评分术语命中数 | 每条均高于 whisper，均值 **2.42×**，最低一条 1.22×，**无一条落后** | 基准 |
| 繁体输出率 | 全程 **0.0%** | 最高 21.4%，长音频 0.6%–3.1% |
| 重复片段（6 字串出现≥3 次） | **55** | **256** |
| 失败/退化 | 零失败 | 2 次静默卡死；157 分钟级长音频触发 `online repetition guard aborted decoding`（解码退化为循环输出） |
| RTF（8 核 CPU） | 0.18–0.42 | 0.25–0.43 |

口径说明：上表"评分术语命中数"是 37 个业务词在转写文本中的命中条数，衡量的是**召回**，不等于字准确率。CER 以云端转写为基准计算时 Dolphin 为 46.5%、whisper 为 62.3%，但云端本身也不是金标准，该数值只作相对参考，不宣称绝对准确率。

逆证据（必须记住 Dolphin 不是万能的）：

1. 中文数字金额形态，见第三节。
2. 人名/称谓不可靠：15:15 试驾报幕"张婷的客户靳先生"，Dolphin 转成"张鼎的客户晋荣红"，whisper 转成"金融红"。**姓名一律不能作为配对依据。**
3. 泛化词仍会丢整词：湿纸巾曾在个别段落被转成"到十斤"，B8 类加分项不能只靠 Dolphin 单侧确认。

## 三、金额：中文数字必须解析

Dolphin 输出的金额是中文数字（"十二万九千九""五万零八百"），全批阿拉伯数字金额命中数为 0。直接跑 `\d{5,}` 类正则会把 E2 报价项全部漏采。

处理要求：

- 报价、优惠、返息、补贴额度、订金等**一切金额**，先做中文数字归一化再匹配；脚本 `scripts/amount_zh.py` 可做换算，但"七万零九八""五万八二十四"这类数字粘连会算错，**换算结果必须回听确认**才能写进 job。
- 报告中出现的金额一律写阿拉伯数字，并标注"据原音 X 分 Y 秒"。
- 判定价格合规前，金额要落到具体车型配置，与本技能价格政策文件逐条核对，不能只凭转写文本下"违规"结论。

## 四、缺少说话人分离的连带约束

Dolphin 不输出 speaker 标签，因此以下项目不能只凭"文本里出现了"就归到销售头上：

| 项目 | 处理方式 |
|---|---|
| B3 自我介绍、询问称谓、礼貌沟通 | 必须结合上下文确认是销售在自报；必要时切原始分声道用 Turbo/Large 复核。录音起点晚于进店寒暄的，是否已自我介绍记"待核实"，不得按已完成处理 |
| B2 服务态度 | 客户爆粗口、客户之间谈论，不得计入销售 |
| 客户离店后的私下评论 | 仍按 6.0-G 约定不纳入评分，但要在管理提示中记录 |
| 意向等级 | 必须看后段购车/订车/提车表述，且确认是谁在说 |
| 两次独立试驾邀约 | 邀约必须是销售对客户说；客户之间"要不要去试"不算 |

无法确认说话人且影响给分时，按既有两轮收口规则记为待核、不获分，不得猜测归属。

## 五、与固定 CLI 的关系

`scripts/scoring_pipeline.py` 的 `transcribe` 命令内部仍走 whisper，自 2026-11-14 起其产出**只用于** B3 分声道、Turbo 对照和历史任务复现，不得再当作全量主转写：

- 全量主转写唯一的权威产物是 `asr_dolphin.py` 生成的 `dolphin.jsonl`（或等价的 `transcript.json` 命名）。
- 语义审读、候选扫描、试驾 timeline、意向判断一律基于 `dolphin.jsonl`。
- `scoring_pipeline.py` 的 preflight / rules / plan-review / adjudicate / publish 等规则与门禁环节继续使用，不受本次切换影响。
- 若某单只有 whisper 文本而没有 `dolphin.jsonl`，视为该单未完成主转写，不得直接出图。

## 六、失败与回退

- 单条转写失败：先检查 `dolphin.log`，常见原因为 VAD 模型缺失或音频为异常采样率；VAD 模型缺失时按 `iic/speech_fsmn_vad_zh-cn-16k-common-pytorch` 补下，不要改走 whisper。
- 只允许一次重跑。重跑仍失败，再用 whisper-small 兜底并**在 job 与审计中显式标注 fallback**，报告不得把 fallback 结果当作 Dolphin 主转写。
- 转写前必须先看原始音频的采样率与声道：立体声原文件保留，16 kHz 单声道 wav 只作主转写，B3 前三分钟仍按原声道复核。

## 七、批次执行约定

- 队列按"短 → 长"排序，一条音源只成功全量转写一次，已有 `dolphin.jsonl` 的跳过。
- 同一批次内不并发多组线程抢 CPU；默认 6 线程，长音频可降到 4。
- 每日批次结束后，把各条 RTF、段数、失败情况记入当日记忆，便于发现模型退化。
