# 高影响证据二次复核规范

## 固定版本与目标

- 当前确定性规则版本：`6.0-G-HB-2026-08-27-r1`。
- 全量转写用于快速发现候选，不直接决定高影响结论。
- 高影响候选必须从原始16 kHz单声道PCM WAV切出带前后文的短片段，并使用 `ggml-large-v3-turbo-q5_0.bin` 或当前已验证的同等高精度本地模型二次转写。
- 完整转写、局部音频和证据审计文件均为内部材料，不作为默认交付物。

## 必扫候选

整条录音和末段都要扫描，至少覆盖：

1. 客户主关注车型、车系、具体配置、续航和版本。
2. 金额、备案价、现金优惠、返息、补贴、保险、服务费、上牌、赠品、保养和预计交期。
3. 第一次与第二次试驾邀请；客户明确同意、拒绝或含混回应；试驾登记、出发、驾驶和结束证据。
4. 购车、订车、锁车、订金和提车时间，尤其是录音后25%的“今天、明天、三天内、本周内、月底前”等表达。
5. 湿纸巾、星巴克实际饮用等加分证据。
6. H否决项、客户明确不需要某项服务的NA依据，以及任何可能导致自动处罚的证据。

`scripts/evidence_candidates.py`负责全量扫描、候选合并、切片、Turbo复核和证据审计。生产用法必须同时传入初次JSONL、原始WAV、输出目录和现有 `transcribe_incremental.py`；不得只运行候选扫描后跳过局部复核。

```powershell
python scripts/evidence_candidates.py `
  --transcript initial.jsonl `
  --audio source.wav `
  --out-dir evidence-review `
  --transcriber work/transcribe_incremental.py
```

## 冲突与采用规则

- 每个候选记录：类别、初次转写、二次复核、原始时间戳、采用结论、判定依据、结构化信号和状态。
- 金额、车型/配置、试驾行为、同意/拒绝、购车时间或加分实体不一致时，状态必须是 `needs_manual_review`，采用结论留空。
- 人工继续回听后，可把状态改为 `confirmed` 或 `unresolved`，并填写采用结论和判定依据；不得删除冲突痕迹。
- `unresolved`等同“待核实”：不得据此加分、判H、判价格违规、提高意向等级、记NA或自动处罚。
- 没有候选不等于不存在。审计文件必须在`coverage`中记录每一类已扫描；H项、湿纸巾、星巴克等无候选时标`scanned_no_candidates`。

## 评分前一致性检查

运行：

```powershell
python scripts/validate_score_job.py --job job.json --audit evidence-review/evidence-audit.json
```

校验必须通过：

- 规则版本固定且一致；A-G模块适用满分之和等于`100-NA`；模块实得之和等于`base`。
- 使用允许分值，按`floor(min(100, base/(100-NA)*100+bonus))`复算最终分。
- 负激励由复算后的最终分确定，不接受自然语言或旧报告覆盖。
- 车型、严管、意向、试驾、报价、加分、H和NA均有时间戳审计覆盖；高影响冲突为零。
- E2得3分时，二次复核证据必须同时覆盖车型/价格、付款或金融、费用、赠品和明确交期。

## 回归用例

- 张恒超—吴先生：必须发现录音后段“3天内/本周内订车”类证据，防止只看前段而误判C级。
- 付世雄—徐先生、张恒超—吴先生：必须发现湿纸巾候选；湿纸巾只有局部高精度确认后才能加3分。
- 上述两条的E模块必须按报价五要素复核；缺少赠品或明确交期时，E2不得因长篇报价而自动得3分。
