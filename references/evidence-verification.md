# 高影响证据二次复核规范

2026-10-10起按[服务评分补充](service-scoring-policy.md)核验C/E/F NA、E2缺项、B8星巴克介绍和湿纸巾提供，以及恢复的C5/D8超额加分。全部NA条件见[矩阵](na-decision-matrix.md)，证据来源必须逐项对应。

## 2026年10月9日本地反馈流程优先口径

用户已授权实施workflow-feedback-2026-10-09-v1。本地按[workflow-optimization.md](workflow-optimization.md)完整语义审读、逐候选相关性筛选及定向原音复核；B3各原始声道仍必查。带精确转写哈希的semantic_scan合同替代旧固定试驾大范围扫窗门禁，不把被排除窗写成已ASR复核。第一轮Turbo、第二轮疑点短窗/分声道/Large，仍含混保留unresolved并按闭环零获分或非计分待核收口；未做审读/复核仍阻断。旧quality=ok不是语义正确，失败结果和稀疏/套话标志保留，不反复恢复无关等待区。新本地不自动跑Turbo全量shadow。此节优先于下文旧逐候选复核和未决一律阻断叙述；云端合同不变。

## 固定版本与目标

- 当前确定性规则版本：`6.0-G-HB-2026-09-14-r3`；价格政策版本`HB-2026-09-17`。r1/r2仅用于保持历史任务可复核，不用于后续新录音。
- 全量转写用于快速发现候选，不直接决定高影响结论。
- 高影响候选通常从16 kHz单声道PCM WAV切出带前后文的短片段。本地任务使用`ggml-large-v3-turbo-q5_0.bin`或当前已验证的同等高精度本地模型；云端任务使用随云端Worker独立部署的`large-v3-turbo`。云端任务不得借用正在运行的本地Worker复核。原始文件为双声道或多声道时，不得只保留单声道转码：必须保留原文件，并为前三分钟B3及其他争议高影响窗口分别切出各声道和混音片段。
- 完整转写、局部音频和证据审计文件均为内部材料，不作为默认交付物。

## 必扫候选

整条录音和末段都要扫描，至少覆盖：

1. 前三分钟B3礼仪：自我介绍、询问称谓和礼貌沟通；原文件为多声道时必须逐声道扫描，主转写无候选仍须完成固定窗口复核。
2. 客户主关注车型、车系、具体配置、续航版本；用于识别客户意向及匹配报价，不核实续航、电机、平台等技术参数或专业说法的真实性。
3. 先按price-scope-2026-10-09-v4筛范围：合规仅核自律会规定的价格、赠品及金融政策，包括范围内备案价、现金优惠、返息、赠品和禁止折抵事项，范围内金额仍须原音核验。专业知识、全部补贴/置换政策（包括金额及补贴报价算术）和标准未规定的税险政策/金额，不作为高影响真实性核验事项，不外部查询或追加复核，不构造未决计分事实、不阻断出图。实际报价组成、预计交期及销售向客户讲解内饰颜色等服务动作仍按规则取证；客户是否确认另行记录，外观与内饰颜色不得相互替代。
4. 第一次与第二次试驾邀请；客户明确同意、拒绝或含混回应；第二次邀约后是否表示“下次再试/改天再试”；客户是否明确约定下次试驾的具体日期/时段；试驾登记、出发、驾驶和结束证据。
5. 购车、订车、锁车、订金和提车时间，尤其是录音后25%的“今天、明天、三天内、本周内、月底前”等表达。
6. 茶点品类与实际提供行为；“有零食”只证明存在零食，不能自动证明至少三类小食。
7. 湿纸巾提供、星巴克简单介绍及C5/D8超额表现等加分证据。
8. H否决项、客户明确不需要某项服务的NA依据，以及任何可能导致自动处罚的证据。

`scripts/evidence_candidates.py`负责全量扫描、候选合并、切片、Turbo复核和证据审计。本地现行任务保持原调用：传入初次JSONL、原始WAV、输出目录和现有`transcribe_incremental.py`。云端任务还必须传入`transcription-audit.json`，并按 [transcription-routing.md](transcription-routing.md) 核验腾讯统一主转写和云端复核身份。任何环境都不得只运行候选扫描后跳过局部复核。

### 试驾专项防漏判协议

- 全量主转写必须执行高召回语义扫描，除“试驾/试乘”外还要覆盖“开一下、开一圈、感受一下、体验一下、再开一次”等表达，以及“试价、市价、车架”等常见近音误转。近音命中只生成候选，不能直接确认得分。
- 无论关键词是否命中，候选器都要生成并复核前15分钟、录音最后25%和每个报价窗口前后90秒的`test_drive_sweep`固定窗口。这里的“全录音扫描”是完整主转写语义扫描加固定高精度窗口复核，不表示把整条录音重复跑一遍Turbo。
- 试驾事件按`invite/agree/refuse/scheduled/deferred/paperwork/depart/dynamic/return/repeat`记录到有序时间线。手续证据与动态驾驶、返回或再次试驾证据组合时，形成`actual_drive_chain=true`；“再次试驾”必须触发对前段5至40分钟的回溯核验。
- 同一或重叠时间窗生成的重复邀约不得计作两次。默认相隔不足45秒的邀约候选合并为同一事件；确有独立轮次时，人工审计须记录不同时间窗和采用理由。
- D项为0、NA或实际试驾分档前，都必须完成专项窗口。审计缺少`full_recording_trial_sweep=true`、存在未复核窗口，或实际试驾链与D项零分冲突时，校验器必须阻止发布。

```powershell
python scripts/evidence_candidates.py `
  --transcript initial.jsonl `
  --audio source.wav `
  --out-dir evidence-review `
  --transcriber work/transcribe_incremental.py
```

云端调用在上述参数中增加：

```powershell
  --transcription-audit transcription-audit.json
```

## 冲突与采用规则

- 每个候选记录：类别、初次转写、二次复核、原始时间戳、采用结论、判定依据、结构化信号和状态。
- 多声道复核还必须记录原始声道数、采用声道、窗口范围和各声道转写结果。混音未识别但某一原始声道清晰识别时，不构成冲突；采用清晰声道，并说明混音漏检原因。
- 用户提供的纠错、时间点或行为描述只登记为`user_claim`，初始状态必须为`needs_manual_review`；原始音频复核确认后才能改为`confirmed`并影响评分。无法确认时标`unresolved`，不得按用户陈述直接修改结果。
- 金额、车型/配置、试驾行为、同意/拒绝、购车时间或加分实体不一致时，状态必须是 `needs_manual_review`，采用结论留空。
- 人工继续回听后，可把状态改为 `confirmed` 或 `unresolved`，并填写采用结论和判定依据；不得删除冲突痕迹。
- `unresolved`等同“待核实”：不得据此加分、判H、判价格违规、提高意向等级、记NA或自动处罚。
- 没有候选不等于不存在。审计文件必须在`coverage`中记录每一类已扫描；H项、湿纸巾、星巴克等无候选时标`scanned_no_candidates`。

## 评分前一致性检查

运行：

```powershell
python scripts/validate_score_job.py --job job.json --audit evidence-review/evidence-audit.json
```

校验必须通过：

- 规则版本固定且一致；A-G模块适用满分之和等于`100-NA`；模块实得之和等于`base`。
- 本地job缺少云转写审计时保持兼容。云端job的`transcription_route.schema_version`必须为`byd-transcription-pipeline-v2`，主转写必须是腾讯`tencent_rec_file`/`16k_zh_en_2.0`/`mixed_zh`且成功，无本地主转写fallback；高影响窗口必须由云端`large-v3-turbo`完成第二遍复核。
- `cloud_shadow`固定不发布、不通知、不计月报；它只能保留candidate对照结果，不能通过最终报告门禁。
- 使用允许分值，按`floor(min(100, base/(100-NA)*100+bonus))`复算最终分。
- 负激励由复算后的最终分确定，不接受自然语言或旧报告覆盖。
- 车型、严管、意向、试驾、报价、加分、H和NA均有时间戳审计覆盖；高影响冲突为零。
- E2得3分时，二次复核证据必须同时覆盖车型/价格、付款或金融、费用、赠品、明确交期和销售对客户的内饰颜色讲解；`job.json`须记录讲解内容、客户是否确认及时间戳。客户未确认选择不单独扣E2；只有外观颜色或无法证实销售实际讲解内饰时，不满足内饰要素。
- B3得3分时，审计必须覆盖前三分钟的自我介绍、询问称谓和礼貌沟通；原始文件为多声道时必须包含分声道复核记录。
- 任何用户临时口径必须写入job或审计，并与得分、扣分理由、明细行、默认项说明和最终PNG一致。

## 星巴克介绍独立复核（2026-10-05起）
每条录音全量语义扫描星巴克/近音、咖啡、饮品介绍和送达情境，并用Turbo复核相关原音窗口。候选类别 `starbucks_introduction` 与 `bonus_starbucks` 分开：介绍/提供/饮用三种行为分别记录；销售对客户明确点名本店星巴克咖啡即支持已介绍，不要求客户实际饮用。客户自行提及或同事私聊不能替代销售介绍。
没有关键词候选仍须复核点饮品、端送咖啡等茶点窗口，再将结论记录为已介绍、未介绍或待核实。未介绍表示录音复核未核验到明确品牌介绍，不作事实缺失的绝对断言；多声道疑点按原规则复核各声道。审计 `starbucks_introduction` 保存全文扫描完成标志、状态、复核时间、窗口、声道、模型、采用理由；阳性候选写 `introduced_to_customer: true`。旧版仅管理提示；service-policy-2026-10-10-v1起介绍本身是B8星巴克+3的条件，仍须保留介绍/提供/饮用三种独立状态，不能重复加分。


## 固定复核缓存与试验隔离

按workflow-optimization.md执行：重叠窗口可合并，缓存只在同一接待目录内、相同音源哈希/原始声道/时间窗/模型文件/参数/质量脚本下复用已通过的结果；缓存不能把主转写变成独立二次复核。失败窗口保留原结果，再切60秒短窗修复；仍失败时原始分声道/large裁决后再出报告。事实状态与复核完成状态分开，未决不得用统一赋值消除。B1的Turbo主转写只进入shadow，正式评分继续现行small加二次复核，B3强制原始各声道条件继续执行。

## 已授权的本地D语义裁决
用户2026-10-06要求将本次改进同步全局技能。后续本地D可按[trial-semantic-policy.md](trial-semantic-policy.md)形成语义判断，无需人工听辨。全量主转写、规定Turbo/Large窗口、原始声道及质量检测仍执行；主模型独立审视支持和相反证据。语义已裁决不改成直接事实confirmed，不创造test_drive_actual阳性。不能认定“客户亲自驾驶”而只支持试乘时如实写试乘。
